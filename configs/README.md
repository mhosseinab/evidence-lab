# Provider configuration and decoding contract

`mock.yaml` exercises deterministic excerpts and explicit adversarial fixtures. It makes no model calls and establishes no semantic quality result. Copy `live.example.yaml` to a private configuration file to supply complete operation URLs, model identifiers, credentials, input limits, supported chat parameters, and dated token prices. Positive total and matching phase caps plus the persistent call ledger are required before live requests can run. API keys may be direct values or one explicitly selected environment/file reference. Relative secret files resolve against the configuration file's directory. Selecting a comparison profile with `config.with_roles(...)` validates the new active profile and resolves its references without changing the original configuration.

OpenAI-compatible profiles are the default. Native Clef requires both explicit role selection and `runtime.require_openai_compatible: false`; its configured endpoint is the complete Workers AI operation URL and its body model is separately `clef` or `clef-flash`. There is no inferred Chat Completions route, parameter discovery, model download, or automatic provider fallback. Input allowances apply to the complete serialized request, including prompts and schemas. Declared headroom mitigates hosted truncation risk; it cannot prove that a server did not truncate. Answers and evidence are never silently shortened to fit.

## Shared runtime and evaluation decoder

Interactive generation and evaluation candidate generation use the same request body and universal decoder: strict JSON with no duplicate keys, recoverable nonempty `blocks[].text`, and identical configured whole-answer byte and block-count caps. A universal JSON/text decoding failure may receive one format retry within the profile's two-attempt maximum. Refusals, abnormal length termination, unsupported tool responses and known input/output budget failures are terminal.

Once an answer is universally decoded, a `Draft` schema violation is terminal in interactive generation and does not receive another generation attempt. The evaluator retains that exact decoded candidate for variant A, then applies schema and citation checks beginning with B. Valid candidates have the same hash as the corresponding typed `Draft`. This keeps the first decoded answer shared across A–D and prevents an interactive schema retry from selecting an answer that was absent from the evaluation. A semantic rejection may trigger the separately bounded content repair; that repair uses the same evidence and requires a complete new verification.

Chat verification returns labels only. Native Clef retains its actual choice distributions as uncalibrated scores; acceptance thresholds belong to the frozen policy. Every answer block and all three global checks must appear exactly once, and application-generated hashes bind the result to the exact draft, evidence and verification round. HTTP failures, incomplete coverage, malformed responses and exhausted limits remain technical outcomes, not factual abstentions.

Every remote attempt reserves budget before transmission. Unknown or inconsistent usage keeps the conservative reservation. Usage-based cost reconciliation uses the configured token rates and is not a provider invoice. Global and profile concurrency limits are enforced both locally and through the persistent ledger; a reserved slot lasts through the remaining run deadline so database latency cannot cause premature reuse.

Run application tasks from the repository root. They default to `configs/mock.yaml`; select a private file with `CONFIG=configs/private.yaml`, for example `task app:cli CONFIG=configs/private.yaml -- config-check`. Compose uses its existing `RAG_CONFIG` setting: `RAG_CONFIG=./configs/private.yaml task compose:up`. No configuration or secret file moves into the application package.
